# Conception : du banc au harnais automatique (48 h, sécurité, notification)

Date : 2026-11-18. Statut : validée (choix de l'auteur du banc le 2026-11-18 et 2026-11-19).

## But

Chaque nouveau modèle repéré par ai-radar passe le banc dans les 48 heures qui suivent sa publication, en plusieurs passages espacés, sans intervention. Le code produit est noté sur deux axes indépendants : **fonctionnel** (tests cachés, existant) et **sécurité** (tests d'intrusion cachés, fuzzing, analyse statique). À la fin, une notification macOS ouvre le rapport. La grille de ressenti, la relecture et la publication restent humaines.

## Décisions

|---|---|---|

Les outils manquants sont installés (Homebrew de préférence, `registry.npmjs.org` étant bloqué sur la machine). Un éditeur sans outil installé : notifié « détecté, pas lançable », jamais mesuré. |
| D2 | Modèles exclus | **Claude Fable (toutes versions) n'est pas autorisé** : liste d'exclusion dans `bench/watch.json`, vérifiée aussi par le lanceur. Variantes « -pro » exclues par défaut (coût). |
| D3 | Premiers rapports | Dans l'ordre : **Claude Opus 5.5** (référence, hors fenêtre de sortie), **Gemini 4 Carbon** (hors délai, publié le 10/11), **GPT-6.2 Astra** (fenêtre jusqu'au 19/11 18:00 UTC). Un rapport hors fenêtre porte la mention « hors délai ». |
| D4 | Sécurité | Périmètre complet : attaques cachées + mutants vulnérables sur les 5 tâches, fuzzing différentiel, semgrep + gitleaks, 2 tâches dédiées (`secu-fichiers`, `secu-jeton`). Pas de juge LLM dans la note ; une revue CodeGuard par LLM peut figurer en annexe, sans note. Test d'une appli HTTP avec ZAP : v1. |
| D5 | Lancement | **Automatique**, avec 1 h pour annuler après la notification de détection, et un budget plafond par modèle. |

## Architecture

```
~/.ai-radar/radar.db ──(lecture seule)──> bench/radar.py ──┐
bench/watch.json (éditeurs, exclusions, budget) ───────────┤
launchd (toutes les heures) ──> bench/routine.py <─────────┘
                                   │  état : results/_routine/state.json
                                   ├─> bench/run.py --append-run   (passage k : fonctionnel + attaques)
                                   ├─> bench/security.py           (semgrep, gitleaks → SARIF)
                                   ├─> bench/report.py + build_site.py
                                   └─> bench/notify.py
```

### bench/radar.py
- Ouvre `radar.db` en `mode=ro` (URI SQLite). Table `items` : `category='model'`, `source='OpenRouter'` (les doublons Hugging Face sont ignorés), `published_at`, `first_seen`.
- Garde : éditeur suivi (`watch.json`), non exclu (Fable, `-pro`, motifs configurables), publié il y a moins de 48 h (ou forcé à la main : `routine.py add <id>`).
- Traduit l'identifiant en agent : `anthropic/claude-opus-5.5` → gabarit `claude` avec `--model claude-opus-5-5` ; `openai/gpt-6.2-astra` → gabarit `codex` ; `google/gemini-4-carbon` → gabarit `gemini`. Les règles de traduction sont dans `watch.json`.
- Santé de la source : si ai-radar n'a pas fini de collecte réussie depuis plus de 30 h (table `runs`), la routine notifie « ai-radar muet ».

### bench/routine.py
- Appelée par launchd toutes les heures (`StartInterval` 3600 ; launchd rattrape au réveil). Idempotente, verrou fichier.
- Sous-commandes : `tick` (défaut), `status`, `skip <modèle>`, `add <id radar>` (forcer, y compris hors fenêtre), `run-now <modèle>`.
- Machine à états par modèle : `detecte → passage1 → passage2 → passage3 → rapport → notifie`, plus `annule`, `budget_depasse`, `non_lancable`.
- H = `published_at`. Passage 1 à détection + 1 h ; passage 2 à ≥ H + 12 h ; passage 3 à ≥ H + 24 h. Si la détection est tardive, les passages restants se resserrent pour finir avant H + 44 h ; au-delà de H + 48 h, ils s'enchaînent et le rapport porte « hors délai ».
- Un passage = le banc complet une fois (lot public, plus `tasks-private/` s'il existe), fonctionnel et attaques.
- Échec extérieur au modèle (quota, réseau, `is_error` de l'outil, sortie illisible) : relancé 2 fois au plus, noté. Échec du modèle : jamais relancé.
- Budget : somme des `cost_usd` connus ; au-delà du plafond, arrêt + notification. Un outil qui ne donne pas le coût (abonnement) : plafond en nombre de passages.
- Horloge injectable (tests).

### bench/run.py (modifications)
- `--append-run` : ajoute un passage numéroté au JSON de la tâche au lieu de l'écraser ; chaque passage garde date, version d'outil, commit du banc, modèles réellement utilisés (`modelUsage` de `claude`).
- Refus de lancer un agent dont la commande contient un modèle exclu (`watch.json`).
- Notation des attaques : après les tests cachés, copie de `src/` dans un troisième dossier temporaire, ajout de `hidden-attacks/`, même mécanisme de jeton (`RESULT <jeton> passed=N total=N`), nombre d'attaques déclaré dans `task.json` (`attacks`, avec pour chacune `id`, `famille`, `exigee: true|false`). Chaque attaque a un délai et la JVM une limite mémoire (`-Xmx`) : un blocage ou un `OutOfMemoryError` compte comme faille.
- Gabarits `codex-jsonl` (existant) et `gemini-json` (nouveau, format à vérifier au premier passage) pour lire tokens et coût.

### Axe sécurité
- `tasks/<tâche>/hidden-attacks/` : tests d'attaque Java 17 pur, harnais `Check`.
- `tasks/<tâche>/mutants-vuln/<famille>/` : la référence avec une faille plausible. `run.py --check` exige : référence qui résiste à toutes les attaques, chaque mutant vulnérable qui tombe sur au moins une attaque de sa famille.
- Fuzzing différentiel : générateur à graine fixe par tâche (`hidden-attacks/Fuzz.java`), comparaison à la référence compilée dans le même dossier de notation sous un autre paquet ; même résultat ou même type d'erreur documentée.
- Attaques par tâche :
  - `prd-config` : expansion exponentielle de `${}`, cycle long, clé géante.
  - `prd-facture` : montants géants, nombre de lignes énorme, caractères de contrôle et Unicode, contenu injecté dans les messages d'erreur.
  - `prd-horaires` : milliers de règles, heures hors bornes, chaînes mal formées.
  - `bug-pagination` : taille négative, nulle, `Integer.MAX_VALUE`, dépassement de `page × taille`.
  - `refacto-tarifs` : quantités limites, dépassement d'entier ; aucune faille absente de l'original.
- Tâches dédiées : `secu-fichiers` (stockage sous une racine : traversée `../`, chemin absolu, encodage, lien symbolique, noms vides ou réservés) ; `secu-jeton` (HMAC avec `javax.crypto` : algorithme « none », comparaison non constante, expiration, signature tronquée, clé faible).
- `bench/security.py` : semgrep avec règles locales `bench/semgrep/` (tirées de Project CodeGuard, sans registre en ligne) et gitleaks sur les artefacts ; SARIF dans `results/<modèle>/security/`. Compte par gravité, sans effet sur la note de réussite.
- Rapport : par tâche, Fonctionnel k/3, Attaques exigées, Attaques implicites, Statique (par gravité). Pour un lot privé, aucun nom d'attaque publié.

### Isolation
- Pattern de `talks/harness-teardown/teardown/run.py` : enveloppe de conteneur (`podman`, installé) qui ne monte que le dossier de travail. Option `container` par agent dans `agents.json` ; recommandée pour un rapport public, pas obligatoire pour la routine v0 (les outils natifs et leurs connexions vivent sur l'hôte).

### bench/notify.py
- `terminal-notifier -title … -message … -open file://<rapport>` si présent ; sinon `osascript` (texte en argument, comme `day-harness/dayharness/reminder.py`) puis ouverture du rapport dans Chrome.
- Notifications : détection (avec `routine.py skip <modèle>`), non lançable, ai-radar muet, budget dépassé, rapport prêt (k/3 fonctionnel, attaques, mention « ressenti à noter »).

### bench/install_routine.sh
- Écrit `~/Library/LaunchAgents/local.dev-model-reports.routine.plist` (toutes les heures, journaux dans `~/Library/Logs/dev-model-reports.log`), `launchctl bootstrap` ; `--uninstall`.

## Tests (sans modèle, sans launchd)
- Faux `radar.db` dans un dossier temporaire : modèles dans et hors fenêtre, Fable, `-pro`, doublon Hugging Face.
- Horloge injectée : chaque transition, rattrapage après veille, resserrement, hors délai, annulation, budget dépassé, échec extérieur relancé.
- Faux agents existants + nouveau faux agent « vulnérable » (copie un mutant vulnérable) : fonctionnel réussi, attaques échouées.
- `--check` couvre attaques et mutants vulnérables sur les 7 tâches.
- Notifieur remplacé par un enregistreur. CI inchangée : aucun modèle, aucune notification.
