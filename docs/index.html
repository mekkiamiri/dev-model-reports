dev-model-reports · banc v0

Le score dit record.
Et sur du vrai code ?

Chaque nouveau modèle arrive avec un score record. Ici, il passe le même banc de tâches de développeur Java dans les jours qui suivent sa sortie : construire à partir d'un PRD avec des tests cachés, corriger un bug, refactorer. On publie la réussite, le temps, le coût, et une grille de ressenti fixe.

mesures à venir Le banc tourne (tests verts, faux agent en CI). Aucun modèle réel n'a encore été mesuré.

Comment ça marche

  1. L'agent reçoit un dossier neuf : la tâche, le PRD, le contrat d'interface. Rien d'autre.
  2. Quand il a fini, on applique des tests d'acceptation qu'il n'a jamais vus. Tout ou rien, sans juge LLM.
  3. On relit son code et son résumé avec une grille fixe de 7 critères. Chaque note cite une preuve.

Chaque tâche est vérifiée en CI : la solution de référence passe, le point de départ échoue, et des « mutants » (la référence avec une erreur plausible) échouent aussi.
