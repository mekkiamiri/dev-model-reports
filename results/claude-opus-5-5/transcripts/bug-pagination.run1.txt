# Message final
J'ai corrigé le bug : avec 20 commandes et 10 par page, l'écran affiche maintenant « Page 1 sur 2 », la page 3 vide a disparu et « Suivant » est inactif sur la page 2. Les 4 tests existants passent.

**Cause.** Dans `Paginator.pageCount()`, le calcul était `items.size() / pageSize + 1`. Il ajoutait toujours une page de plus. Quand le nombre de commandes est un multiple exact de la taille de page (20 / 10), on obtenait 3 pages au lieu de 2. La page 3 était vide, et comme `hasNext(2)` s'appuie sur ce nombre, « Suivant » restait actif en page 2. Avec 25 commandes, le +1 tombait juste par hasard, d'où l'absence de bug dans ce cas.

**Correction** (`src/com/example/paging/Paginator.java`) :
- `pageCount()` arrondit maintenant au supérieur, sans dépassement de capacité possible : `size / pageSize + (size % pageSize == 0 ? 0 : 1)`. Une liste vide garde sa page unique, comme l'exige la documentation de la classe (« Page 1 sur 1 »).
- Petite modification en plus dans `page()` : la fin de page se calcule maintenant par `from + Math.min(pageSize, size - from)`. L'ancien `from + pageSize` pouvait déborder avec une taille de page très grande. Le résultat est le même dans les cas normaux.
- Les signatures publiques n'ont pas changé, et je n'ai ajouté aucun fichier dans `src/`.

**Vérifications.** En plus des tests existants, j'ai lancé un petit programme jetable, supprimé ensuite. Résultats :
- 20 commandes / 10 par page : 2 pages, `hasNext(1)` vaut vrai et `hasNext(2)` faux, la page 2 contient les commandes 11 à 20, et demander la page 3 lève bien l'exception.
- Autres cas : 1 par page donne 20 pages, `Integer.MAX_VALUE` par page donne 1 page de 20 éléments, 1 seul élément donne 1 page, et 20 éléments par 3 donnent une page 7 contenant `[19, 20]`.

**Non vérifié.**
- Les tests d'acceptation, que je n'ai pas vus.
- L'interface qui affiche « Page X sur Y » et le bouton « Suivant » : elle n'est pas dans le dossier. Je suppose qu'elle utilise `pageCount()` et `hasNext()`.
- Je n'ai pas modifié `hasNext` pour des numéros de page invalides (0 ou négatifs, qui renvoient `true`). Le ticket n'en parle pas.

**Ambiguïtés.** Aucune vraie ambiguïté : la règle « une liste vide a une page » était donnée explicitement dans la documentation de la classe.
