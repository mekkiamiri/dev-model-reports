## Ce que j'ai fait
- **`ConfigException`** : hérite de `RuntimeException` et a un constructeur `(String message)`, comme dans le contrat.
- **`ConfigResolver.resolve(List<String>)`** :
  - **Lecture des couches** : accepte `\n` et `\r\n`. Seul le premier `=` sépare la clé de la valeur, et les espaces autour de chacune sont retirés. Les lignes vides ou qui commencent par `#` ou `!` sont ignorées. Une ligne sans `=` ou une clé vide déclenche une erreur. Si une clé apparaît deux fois, la dernière valeur l'emporte.
  - **Fusion** : les couches sont appliquées dans l'ordre donné. `!unset` (comparé exactement, après retrait des espaces) supprime la clé, et une couche suivante peut la redéfinir.
  - **Variables** : `${nom}` est remplacé par la valeur résolue (les chaînes de variables fonctionnent) ; `${nom:-défaut}` utilise le défaut tel quel ; `$$` donne `$` ; un `$` isolé est conservé. Lèvent une `ConfigException` : variable inconnue, `${` non fermé, nom vide, et cycle (le message contient « cycle »).
- **Tests** dans `test/ConfigResolverTest.java`, hors de `src/`. Ils couvrent les règles du PRD et chaque cas d'erreur. Le premier passage a montré une erreur dans un de mes tests, pas dans le code : j'avais mal écrit le résultat attendu pour un défaut littéral. Après correction, tout passe.

## Ce que je n'ai pas fait ou pas vérifié
- **`javac --release 17`** : la commande a demandé une autorisation, alors j'ai compilé avec `javac -d out …` seulement. Je n'ai donc pas vérifié la version du JDK installé. Le code n'utilise que des API simples de la bibliothèque standard (`trim`, `split`, collections), et ne devrait donc pas poser de problème en Java 17.
- Je n'ai pas testé de très longues chaînes de variables. Si elles provoquent un `StackOverflowError`, il est converti en `ConfigException`.

## Ambiguïtés et choix faits
1. **Fin d'un `${…}`** : il se termine au premier `}`, sans gérer les accolades imbriquées. Le défaut est donc tout ce qui se trouve entre `:-` et ce premier `}`. Par exemple, `${x:-${y}}` donne le défaut `${y` suivi d'un `}` littéral.
2. **Défaut quand la clé existe avec une valeur vide** : la valeur vide est utilisée, pas le défaut, puisque le PRD dit « si `nom` **n'existe pas** ».
3. **Nom de variable** : il est pris tel quel, sans retrait d'espaces. Ainsi `${ a }` cherche la clé « ` a ` ». Seul un nom de longueur nulle compte comme « nom vide ».
4. **Défaut vers une clé en cycle** : si la clé existe mais fait partie d'un cycle, `${a:-d}` lève l'erreur de cycle au lieu d'utiliser le défaut.
5. **Cycles qu'aucune autre clé n'utilise** : toutes les clés sont résolues, donc un cycle lève une erreur même si rien d'autre ne s'en sert.
6. **`!unset` sur une ligne seule** : c'est un commentaire, puisque la ligne commence par `!`. Seule la valeur `clé = !unset` supprime une clé.
7. **`null`** : une liste `null` ou une couche `null` lève une `ConfigException`. Le PRD ne dit rien sur ce cas.
8. **`\r` seul** : il n'est pas traité comme une fin de ligne, car le contrat ne mentionne que `\n` et `\r\n`.
