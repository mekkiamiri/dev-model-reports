## Ce que j'ai fait
- **`src/com/example/config/ConfigException.java`** : la classe d'exception demandée par le contrat.
- **`src/com/example/config/ConfigResolver.java`** :
  - **Lecture des couches** : accepte `\n`, `\r\n` et `\r`. Les lignes vides et celles qui commencent par `#` ou `!` sont ignorées. La clé et la valeur sont séparées au premier `=`. Une clé vide ou une ligne sans `=` lève une erreur.
  - **Fusion** : les lignes sont appliquées dans l'ordre, couche après couche. Une ligne plus tardive l'emporte, que ce soit dans la même couche ou dans une couche suivante. `!unset` retire la clé.
  - **Variables** : gère `${nom}`, `${nom:-défaut}`, `$$` et le `$` isolé. Chaque valeur n'est résolue qu'une fois, et l'enchaînement des clés en cours de résolution sert à détecter les cycles. Le message est de la forme `variable cycle detected: a -> b -> a`.
  - Toutes les erreurs lèvent `ConfigException`, avec la couche et la ligne en cause quand c'est pertinent.
- **`test/ConfigResolverTest.java`** (hors `src/`) : 27 cas qui couvrent le format, la fusion, `!unset`, les variables et toutes les erreurs. Tous passent.

## Ce que je n'ai pas fait ou pas vérifié
- **Compilation avec `--release 17`** : cette commande demandait une autorisation, donc j'ai compilé avec `javac -d out` et le JDK installé. Le code n'utilise que des API disponibles en Java 17 (`strip()`, `List.of`…), mais je ne l'ai pas vérifié avec ce drapeau.
- **Chaînes très longues** : la résolution est récursive. Une chaîne de plusieurs milliers de variables pourrait faire déborder la pile ; je ne l'ai pas testé.

## Ambiguïtés et choix faits
1. **Contenu de `layers`** : j'ai considéré que chaque élément est le **texte** d'une couche, pas un chemin de fichier. La mention des fins de ligne dans le contrat va dans ce sens.
2. **Clé définie mais cyclique** : un cycle est une erreur même si aucune autre valeur ne fait référence aux clés concernées, car toutes les valeurs sont résolues. Il l'est aussi quand la clé est appelée via `${nom:-défaut}` : comme elle existe, le défaut n'est pas utilisé.
3. **Fin d'une variable** : le premier `}` ferme la variable. Un défaut ne peut donc pas contenir `}` : `${x:-${y}}` donne `${y}`.
4. **Séparateur du défaut** : il se trouve à la première occurrence de `:-`. Un `:` seul fait partie du nom.
5. **Espaces dans le nom** : ils ne sont pas retirés. `${ a }` cherche la clé `" a "`, ce qui donnera en pratique une variable inconnue.
6. **Défaut ou valeur vide** : le défaut ne s'applique que si la clé est absente, y compris après un `!unset`. Une clé définie avec une valeur vide garde sa valeur vide.
7. **Ligne `!unset` seule** : comme elle commence par `!`, c'est un commentaire, donc elle est ignorée.
8. **Entrées nulles** : une liste `null` ou une couche `null` lève `ConfigException`.
